# 长片逐段验收

新模式入口：03 视频测试 → 新 Director → 执行方式 → 逐段验收（长片推荐）。原连续整片模式仍可使用。

1. 填写全片视觉风格及每段持续保持的构图、人物、服装、光线要求。这些内容会写入每段实际提交的提示词。包装层不再自动强制真人风格。
2. 每段可以单独选标准或Turbo及标准步数。Ref2VA仍不能使用当前FL Turbo LoRA。时长沿用描述页设置，建议动作单一、对白能在本段完成；不会自动切短或删台词。
3. 先检查下一段，然后生成该段。生成完成保存MP4与实际末帧PNG，进入人工验收；不会自动提交后段。
4. 完整观看构图、角色、服装、画风、动作和声音；通过后，下一接续段使用已通过视频的末帧。不通过时填写问题、改约束/采样或选纠偏首帧，再重做当前段。两次尝试后需修改方案才能继续，已通过前段保留。
5. 纠偏首帧只选02参考图里已采用的完整first_frame素材。先上传或生成并采用，确保姿态和道具状态符合前段结束状态。选入后当前段改用独立I2V，不同时混绑原参考图；这不是强行给FL工作流塞身份参考。
6. 全部通过后才启用合片。独立MiniMaxH3ReviewedJoin节点在CPU连接MP4，SaveVideo保存最终输出，不重新采样。各段尺寸、帧率、编码与音轨布局必须一致；不兼容时拒绝拼接。

逐段记录保存在浏览器，刷新恢复任务轮询。导出记录JSON并另外备份视频/末帧；重做前一次尝试保留在history中。更换剧本、素材、服务或全局参数后需开启新一轮，防止旧结果混入新项目。提交结果未知时必须先核对队列，填写任务ID恢复或明确确认没有提交；不会自动重试。

## 安装

运行scripts/install-director-bridge.ps1，更新__init__.py及checkpoint_join.py；重启8189 Director加载新节点。已有上游Director不改动。CPU合片需要ffmpeg可执行程序在PATH，或已有imageio_ffmpeg。网页开发服务支持热更新，生产服务需重建并重启。

## 验证与边界

38项JS测试、类型检查、lint、生产构建；CPU合片测试验证分段顺序、48帧和音轨保留，以及路径越界/重复视频拒绝。原生图验证只检查节点与展开图，不采样模型。

连续整片模式可配置视觉模型进行人物、服饰、场景、构图与画风的抽样检查；仅技术检查模式不验收这些语义要求。不保证通过增加提示词或关键帧就消除漂移，也不保证标准20步一定优于Turbo。整片完成仍应观看接缝与声音。本轮没有新GPU实测。

## 中断后继续与单段重做
服务重启不清除浏览器进度。使用原浏览器和 http://localhost:3000，不点击“开启新一轮验收”；localhost 与 127.0.0.1 的存储不同。先核对前段已通过和视频、末帧仍可读取。
当前失败段使用“本段重做描述（保留前段验收）”，不会修改原剧本或触发全项目配置变化。保留对白原文与顺序；留空沿用原描述。全片风格留空时保留分镜原风格。
Beat5 漂移复测：标准模式、20步，原分辨率、种子和时长；检查Beat4实际末帧正确后接续。若末帧已经漂移，先修Beat4或选择与其结束姿态匹配的完整双人纠偏首帧；不能把单人定妆图当双人首帧。完整观看后才继续Beat6。

### 浏览器验收记录丢失时
本地开发服务提供“从 Director 找回已生成分段（不重新生成）”。按当前项目名称与段序读取输出目录，验证视频与配套末帧可访问；找回结果均待人工验收，不自动判定通过。存在多个版本时拒绝猜测。逐段重新确认后可重做失败段，无需重新采样前段。可通过 DIRECTOR_OUTPUT_DIR 配置本地输出根目录。部署版不支持本地目录扫描。

## 自动逐段与首尾帧纠偏
连续整片现在通过同一逐段流程执行：主动启动后生成一段、抽取8张画面检查，通过才接续，全部通过自动合片。视觉服务支持百炼或本地Ollama，必须单独配置支持图片理解的模型；剧本分析模型不能代替视觉模型。百炼会接收参考图和抽样帧。检查失败或服务异常即停止，不自动放行、不无限重试。页面需保持打开，刷新后主动继续。对白、声音和完整表演仍需最终观看。
每段显示实际有效采样模式；本段配置优先于整片默认，Turbo实际8步，标准使用所填步数。
Beat6漂移案例：先复查Beat5实际末帧；如果已成单人特写，应从Beat5重做，保留正确Beat1–4。在Beat5选择Beat4已验收末帧作首帧，并可指定同机位完整双人尾帧启用FL2VA；Beat6接续修复后的Beat5，并同样设置双人尾帧。两端锁定不保证中间绝无漂移，仍需检查。

## 卡片操作
每个Beat卡片都有检查、运行、重做按钮，以及当前段视频和验收按钮。检查只验证环境与素材，不启动模型。运行仅对当前可接续段启用，前段未通过时后段不能运行。重做先解锁配置并归档后段；调整后再点击本卡运行，不会因点击重做立即采样。连续整片模式的运行/继续及停止按钮位于所有Beat卡片下方。

## 接续首帧保护
默认启用“提交下一段前检查实际首帧”。手动检查、手动运行和自动整片均在接续提交前调用视觉模型，将实际传入的末帧或纠偏首帧与首段全片基准图比较。人物、服装、场景、构图或画风任一失败，或模型配置缺失、服务异常，均暂停提交并指出应重做上一段或更换纠偏首帧。人工点通过不能替代这道接续检查。用户可以明确关闭保护后人工验收；关闭后不能声称系统会识别语义漂移。系统不自动改写不合格末帧，因为改图可能造成动作跳变；应重做问题段并验收整段。

## 提前准备全部首尾帧
02参考图点击“补齐逐段首尾帧”，保留原母版与已有图片，只追加缺失任务。连续段共用边界图（上一段计划尾帧=下一段计划首帧），独立段另设首帧。先生成并采用母版，再点击生成全部图片逐层推进；派生图等待依赖验收，不会在母版未采用时盲目提交。全部边界图采用后，在视频页点击“绑定已采用的计划首尾帧”，未通过图片验收的段不绑定，已通过的视频段不改动。此时生成使用计划首尾帧FL2VA，视频实际结尾仍须对照目标图验收；不能将计划尾帧存在等同于视频已达到该状态。
