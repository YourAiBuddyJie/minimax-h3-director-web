# 长片逐段验收

新模式入口：03 视频测试 → 新 Director → 执行方式 → 逐段验收（长片推荐）。原连续整片模式仍可使用。

1. 填写全片视觉风格及每段持续保持的构图、人物、服装、光线要求。这些内容会写入每段实际提交的提示词。包装层不再自动强制真人风格。
2. 每段可以单独选标准或Turbo及标准步数。Ref2VA仍不能使用当前FL Turbo LoRA。时长沿用描述页设置，建议动作单一、对白能在本段完成；不会自动切短或删台词。
3. 先检查下一段，然后生成该段。生成完成保存MP4与实际末帧PNG，进入人工验收；不会自动提交后段。
4. 完整观看构图、角色、服装、画风、动作和声音；通过后，下一接续段使用已通过视频的末帧。不通过时填写问题、改约束/采样或选纠偏首帧，再重做当前段。两次尝试后需修改方案才能继续，已通过前段保留。
5. 纠偏首帧只选02参考图里已采用的完整first_frame素材。先上传或生成并采用，确保姿态和道具状态符合前段结束状态。选入后当前段改用独立I2V，不同时混绑原参考图；这不是强行给FL工作流塞身份参考。
6. 全部通过后才启用合片。独立MiniMaxH3ReviewedJoin节点在CPU连接MP4，SaveVideo保存最终输出，不重新采样。各段尺寸、帧率、编码与音轨布局必须一致；不兼容时拒绝拼接。

逐段记录保存在浏览器，刷新恢复任务轮询。导出记录JSON并另外备份视频/末帧；重做前一次尝试保留在history中。更换剧本、素材、服务或全局参数后需开启新一轮，防止旧结果混入新项目。提交结果未知时必须先核对队列，填写任务ID恢复或明确确认没有提交；不会自动重试。

## 安装

运行scripts/install-director-bridge.ps1，更新__init__.py及checkpoint_join.py；重启8189 Director加载新节点。已有上游Director不改动。CPU合片需要ffmpeg可执行程序在PATH，或已有imageio_ffmpeg。网页开发服务支持热更新，生产服务需重建并重启。

## 验证与边界

38项JS测试、类型检查、lint、生产构建；CPU合片测试验证分段顺序、48帧和音轨保留，以及路径越界/重复视频拒绝。原生图验证只检查节点与展开图，不采样模型。

人物、服饰、画风的语义识别尚未自动实现；尺寸/疑似黑边检查仅辅助人工。不保证通过增加提示词或关键帧就消除漂移，也不保证标准20步一定优于Turbo。整片完成仍应观看接缝与声音。本轮没有新GPU实测。
